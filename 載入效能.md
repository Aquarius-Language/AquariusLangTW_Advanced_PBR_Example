# PBR startup improvements — 2026-10-15

The slow startup came mainly from asset transport and CPU decoding, rather than triangle count or shader execution. The fixes span this scene and the sibling `AquariusLangTW` language project.

## Causes and changes

1. **Duplicated web assets.** The old exporter placed base64 assets in both `program.json` and the Wasm metadata. Startup fetched these two enormous files sequentially and decoded the same asset strings again when loading textures. The exporter now reuses the language's existing external-asset Wasm transformation and writes binary asset files. Four bounded fetch workers load assets while Wasm compiles; native reads receive byte arrays. Standalone Wasm remains self contained, and older inline browser bundles still load.

2. **JavaScript gzip and byte conversion.** The old texture path performed per-byte base64 conversion, gzip processing in 4 KiB chunks, and whole-buffer validation on large mip chains. Browsers now use bounded native `DecompressionStream`. The checked fflate fallback uses 64 KiB chunks. Android decodes with `GZIPInputStream` into a direct JNI buffer and uploads it without sending hundreds of megabytes through V8. Binary APK assets avoid a second ZIP decompression layer. Exact lengths, gzip checksums, finite components, and allocation bounds remain checked.

3. **Mesh assembly through individual language calls.** The scene parsed 100,629 expanded vertices from JSON and made about 200,000 individual vertex/normal calls. It now calls `Processing.loadMesh` once on an AQM1 float32 position/normal/UV asset. Desktop, web, and Android share the format and expose the usual editable retained shape. Original vertex order preserves the vertex-indexed tangent texture. JSON remains available for rebaking and is excluded from runtime packages.

The original four 4096×4096 material mip chains, 1024 cube environment, irradiance, BRDF LUT, 33,543 triangles, HDR pipeline, and input behavior are preserved. No downsampling or substitute geometry was used.

## Validation and reproduction

- 316 JavaScript runtime tests pass, including binary asset loading, compatibility, bounded decompression, corruption handling, mesh layout, and retained-shape editing.
- 111 relevant .NET packaging, mesh, texture, Android-export, and portable graphics tests pass; two independent GPU tests are disabled by their existing test configuration.
- 17 Android Java unit tests pass, including three new direct-buffer texture tests; the APK builds for arm64-v8a and x86_64. The x86_64 APK successfully renders three frames. ARM64 has not been run on a physical device.
- Windows GPU verification and Chrome lighting, rotation, zoom, and portrait resizing pass. Reference-image errors remain at the previous values: Windows 0.0993 / 0.1165 and browser 0.1241 / 0.1442 mean RGB-channel difference for default / fully lit scenes, with p99 = 1. See `notes/image-comparison.json`.

`建置.ps1` prefers the sibling language project's Release compiler when present; `-Compiler` selects an explicit compiler. A compiler/runtime containing the new `loadMesh` API is required. Rebuild the language with .NET 8 and refresh its Windows runtime pack with `scripts/publish-apphost.ps1` when producing a self-contained EXE.

```powershell
./建置.ps1 -Target web
./建置.ps1 -Target apk
npm run profile:startup
npm run test:browser
python tools/profile-android.py notes/startup-android.json --apk dist/PBR.apk
python tools/compare.py
```

`python tools/pack-mesh.py` regenerates the binary mesh from the retained JSON using only the standard library; the rebake packer also emits it automatically. The browser tools accept `AQUARIUS_PLAYWRIGHT_ENTRY` and `AQUARIUS_PBR_WEB` for an existing Playwright installation or alternate output directory.
